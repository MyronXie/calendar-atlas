# 地点名称匹配规则说明（现行做法与改进方向）

## 1. 数据与字段
- 主库：`user-data/place.csv`（location,address,adcode,lat,lon,firstShown,lastShown,valid,type,labels,aliases）
- 日历：`user-data/calendar.ics`（事件 LOCATION 与正文 `Place：` 行）
- 外部：高德 Web 服务（place/text、place/around、geocode/regeo）、百度地图 web JSON（备选）
- `valid`：`YY/MM/DD`=该日核验在营；`no`=停业；`skip`=待下次验证；空=未核验
- `aliases`：旧名/别名（日历旧名、改名前的名字），匹配时与 location 等同参与索引

## 2. 名称解析与归一化
1. 事件地点 = `LOCATION` + 正文 `Place：` 行（忽略括号内内容差异见下）。
2. 归一化：NFKC、转小写、去标点/空白。
3. **品牌核心 = 括号前的部分**；括号（`(...)`/`（...）`）通常表示**商场/分店/门店位置**，不计入品牌身份。
   - 例：`敏华冰厅(正大广场)` 的品牌核心是 `敏华冰厅`；`翠华餐厅(正大广场店)` 是 `翠华餐厅` —— 虽同商场但**不是同一家**。

## 3. 现行同店判定（由强到弱）
1. **完全同名**（归一化后相等）→ 判为同店/存在。
2. **品牌核心相似**：核心的**连续公共子串**占比较短核心长度 ≥ 0.6 → 疑似改名（连续子串，避免不连续误配，如“敏华冰厅/翠华餐厅”曾因“华…厅”误判）。
3. **同商场 + 核心近似**：品牌核心相似 ≥ 0.45，且括号分店名相同，距离 ≤ 60m → 疑似改名（覆盖“锦至日本料理→锦炙·日料小馆”这类核心差异大但同址同商场的情况）。
4. **近址同名/同址同品牌**：原址周边 ≤80m 有完全同名或同品牌 POI → 存在/改名。
5. 否则按“原址被别家占用/附近无 POI”倾向停业。

## 4. 现行方法的局限（为什么仅靠关键词/字符串不够）
- **简称/别名/谐音/中英混写/错别字**：如 `锦至`↔`锦炙`、`GARLIC BARBECUE`↔`Garlic18小时果木烟熏烤肉`、`太二酸菜鱼`↔`新太二·鲜料川菜`，字符串相似度低但语义可能相同。
- **品牌更迭/联名/副牌**：老店换品牌、同址换招牌，名称几乎无重叠，字符串法会判“停业”。
- **括号含义多样**：多为商场，但也可能是“（1号店）/（旗舰店）/（某某里）”等，一律当分店会漏/误。
- **连锁同品牌多分店**：同品牌到处都有，仅“同品牌”不足以证明**本分店**存在；必须结合地址/门牌/距离。
- **地图代表点误差/搬迁移位**：坐标距离不能直接当不存在证据。
- **同名异地**：同名不同城市，仅靠名称会串。

## 5. 改进方向：大模型语义综合判断
把“待判定地点 + 若干候选（名称、地址、类型、距离、简介/评分/营业信息）”一起交给**大模型做语义判断**，输出：`同店(改名)/搬迁/停业/需人工`，并给出理由。相较关键词法，能处理简称、谐音、中英、品牌更迭、括号歧义等。

建议流水线：
1. **候选生成**（保留现几何+多源召回）：高德 text/around、百度、可选腾讯；按距离/类型/地址粗筛，扩大召回。
2. **语义判定（LLM）**：对每个候选与目标地点，让模型阅读名称+地址+类别+距离+周边，判断是否同一实体及其状态。
3. **人工抽检**：对 LLM 判“改名/搬迁/停业”的低置信项抽检。
4. **落地**：改名（旧名→alias、更新坐标/adcode）、停业（valid=no）、通过（valid=日期）。

## 6. 本轮落地结果（供追溯）
- 剩余 179 条按人工决定：改名 106（含合并 3）、停业 59、直接通过 10、稍后验证跳过 1。
- 现 `place.csv` 约 840 行；`名称不一致`仅剩 1 条（思群堂，按“稍后验证”保留）。

> 说明：以上第 3 节的阈值仍属经验值；后续应以“候选生成 + 大模型语义判定 + 人工抽检”为主，逐步替代纯字符串阈值。
