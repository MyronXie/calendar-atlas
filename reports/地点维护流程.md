# 地点维护流程

在工程根目录运行下列命令。地点主库为 `atlas-data/place.csv`。查询前在当前 PowerShell 会话设置 `AMAP_KEY`。查询结果放在 `reports/`，请先核对再写回。

| 字段 | 含义 |
| --- | --- |
| `location`、`aliases` | 主名称和用分号分隔的别名 |
| `address`、`adcode` | 地址和六位行政区划码，境外行政区划码可留空 |
| `lat`、`lon`、`datum` | 纬度、经度和坐标系。高德返回 GCJ-02 |
| `firstShown`、`lastShown` | 日历首次和最后一次出现的日期，格式为 `YY/MM/DD` |
| `valid` | 日期表示上次核验在营，`no` 表示停业，`skip` 或空值进入下次核验 |
| `type`、`labels` | 地点分类和以分号分隔的标签 |

## 更新日历后同步地点

1. 将新导出的 ICS 覆盖到 `atlas-data/calendar.ics`。
2. 运行 `npm run sync`。根据报告确认直接匹配、待新增和待核对的地点。候选判定见 [地点名称匹配规则](名称匹配规则说明.md)。
3. 核对当天生成的 `日历地点同步_决策_<日期>.csv`。已有地点改名用 `rename`，并在 `location_old` 填主库名称或别名。新地点用 `add`。同一新地点若有多个名称，可在新增后通过地点管理补别名。
4. 按实际生成的文件名执行下方写回命令。同步模式会同时按日历重算库内匹配地点的首次和末次出现日期。

```powershell
npm run apply -- --mode sync --decisions "reports/日历地点同步_决策_<日期>.csv"
```

## 定期核验营业状态

1. 运行 `npm run verify -- --months 3`。脚本跳过已停业记录和最近 90 天核验过的记录。
2. 核对当天生成的报告和 `地点有效性核验_决策_<日期>.csv`。确认仍营业用 `keep`，改名用 `rename`，已停业用 `closed`。资料不足时可移除对应决策行，留待下次确认。
3. 按实际生成的文件名执行写回命令。每次写入前会在 `atlas-data/.backups/` 保存副本。

```powershell
npm run apply -- --mode verify --decisions "reports/地点有效性核验_决策_<日期>.csv"
```

## 决策表格式

```csv
location_old,action,new_name,lat,lon,adcode,note
新地点,add,新地点,31.23,121.47,310115,确认新增
原店名,rename,新店名,31.23,121.47,310115,确认改名
正常营业地点,keep,,,,,更新核验日期
已停业地点,closed,,,,,确认停业
```

`rename` 会保留原名称用于匹配日历。`keep` 和 `rename` 会将营业核验日期更新为当天。地址、分类、标签与坐标系可在 **设置 → 地点管理** 维护。

缺坐标时运行 `npm run pending`，填写生成的待补清单，再把核对过的记录追加或合并到主库。纯本地的日历格式检查使用 `npm run audit`。照片地点提取和商场表维护见 [使用说明](../使用说明.md#从照片提取地点行程)。
