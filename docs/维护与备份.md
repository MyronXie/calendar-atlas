# 维护与备份

## 从零开始验证

安装 Node.js 22 或更新版本，运行 `npm test`。测试使用合成数据，无需安装 npm 依赖。

在**全新测试副本**中创建 `atlas-data/`，从 `tests/fixtures/` 复制 `fixture.ics`、`place.csv`、`config.json`，将 `fixture.ics` 改名为 `calendar.ics`。启动后在时间范围弹窗选「全部」并应用。Windows 启停见[使用说明](使用说明.md#打开和关闭桌面版)。命令行可用 `npm start` 前台运行，按 Ctrl+C 停止。健康检查地址是 `http://127.0.0.1:8787/api/health`。

## 日常维护

- `npm run audit` 生成日历检查报告，`npm run pending` 输出待补坐标地点。地点匹配和确认后写回见[地点维护流程](地点维护流程.md)。
- Outlook 导出的 ICS 若含大量重复的 Word HTML，可运行 `npm run clean:calendar -- --write` 或双击 `tools/清理日历.cmd`。工具先备份，再逐条验证事件，内容一致时才替换。个别事件正文过大时可先用 `tools/Outlook正文转纯文本.cmd` 预览候选再确认修改。后者需要中文界面的 Windows 经典版 Outlook 和 PowerShell 5.1。
- 界面改动刷新页面即可，服务器或其导入模块变动后重启服务。按改动范围验证首屏加载、筛选、触控、分栏、导入和 PNG 下载。

## 移动预览与发布

1. 运行 `node tools/build-mobile.mjs --data-less`，再用 `node mobile/serve.mjs` 在 8790 预览和导入合成文件。构建会重建 `mobile/`。
2. 省略 `--data-less` 会把私人文件复制进移动包。预览服务器监听所有网络接口，含数据包仅在可信网络使用。
3. 提交前用 `git diff --cached --name-only` 和 `git diff --cached --check` 核对范围。检查日历、地点、配置、报告、缓存、照片、密钥和签名均未进入提交或发布包。公共提交也包含 Git 作者邮箱，可在本机用 `git var GIT_AUTHOR_IDENT` 核对。
4. 推送 `main` 后，Pages 工作流跑测试、构建无数据包并检查产物。确认部署成功后，在网页偏好中核对版本。前端资源改动同时验证桌面根路径与 Pages 子路径；PWA 在退出设置或弹窗后应用更新。

## ZIP 备份与恢复

用 `日历足迹.cmd stop` 停止桌面服务，再把源码、公开地图、测试、文档及完整 `atlas-data/` 打包到项目目录外。按需包含 `temps/`，跳过 `.git/`、`mobile/`、`node_modules/`、其他压缩包和密钥。ZIP 含私人数据，保存在受控位置。

恢复时先解压到新目录，检查三份数据文件并运行 `npm test`。替换旧工程前单独保存现有 `atlas-data/`。只恢复某次编辑时，可在 `atlas-data/.backups/` 找对应备份。浏览器偏好和 Git 历史分别迁移。
