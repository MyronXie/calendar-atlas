# Calendar Atlas 维护与备份

## 从零开始验证

安装 Node.js 22 或更新版本，从项目根目录运行 `npm test`。桌面、测试和静态构建都用仓库内模块，无需安装 npm 依赖。套件使用合成数据，HTTP 回归使用独立端口和临时目录。

下面的 PowerShell 命令用于**没有 `atlas-data/` 的全新测试副本**。测试数据使用固定日期，进入桌面版后展开「时间」，再点击总览的「全部」。

```powershell
if (Test-Path -LiteralPath 'atlas-data') { throw '已存在 atlas-data，请在全新测试副本执行' }
New-Item -ItemType Directory -Path 'atlas-data' | Out-Null
Copy-Item -LiteralPath 'tests/fixtures/fixture.ics' -Destination 'atlas-data/calendar.ics'
Copy-Item -LiteralPath 'tests/fixtures/place.csv' -Destination 'atlas-data/place.csv'
Copy-Item -LiteralPath 'tests/fixtures/config.json' -Destination 'atlas-data/config.json'
npm start
```

打开 `http://127.0.0.1:8787/`。另一个终端可检查 `http://127.0.0.1:8787/api/health`。修改界面后重载页面，修改服务器或其导入模块后重启。Windows 双击启动或停止的方式见 [使用说明](使用说明.md#打开和关闭桌面版)。

## 日常维护与验证

运行 `npm run audit` 生成本地日历检查报告。运行 `npm run pending` 在 `atlas-data/` 生成待补坐标清单。两个命令都不会写回活动日历或地点主库。需要在线匹配和写回地点时，按 [地点维护流程](地点维护流程.md)先看报告，再执行确认过的决策 CSV。

从客户端（如 Outlook）导出日历并替换 `atlas-data/calendar.ics` 后，运行 `npm run clean:calendar -- --write`（或双击根目录 `tools/清理日历.cmd`）清除 Word 生成的 `X-ALT-DESC` HTML 冗余。该命令先备份到 `atlas-data/.backups/`，用应用自身的解析逐条比对事件内容，不一致即中止；通常减少约 30% 体积。注意这是本地优化，客户端每次导出都会重新带上，属于每次导出后的例行一步。

### 清理 Outlook 导出的 HTML 冗余（完整流程）

Outlook「保存日历」会把事件正文的 Word/HTML 版本写成 `X-ALT-DESC`，常使导出文件膨胀约 30%；正文纯文本其实已在 `DESCRIPTION` 里。分两层处理：

1. **导出后本地清理（每次必做，安全无损）**：替换 `atlas-data/calendar.ics` 后双击 `tools/清理日历.cmd`（或 `npm run clean:calendar -- --write`），先备份、逐条比对、不变才写入，通常缩 30%。等价于删掉重复的 `X-ALT-DESC`。
2. **少数「巨无霸」事件（可选，治本）**：极个别事件正文是 Word 富文本，单条 `X-ALT-DESC` 就约 38KB。可在 Outlook 手动改成纯文本（打开事件 → 点正文 → 设置文本格式 → 更多命令 → 格式 → 邮件格式 → 纯文本 → 保存），或运行 `Outlook正文转纯文本.cmd` 批量处理：脚本先用 RTF 体积筛出候选，默认只预览，确认后才修改；仅支持中文界面 Outlook，须用 Windows PowerShell 5.1 运行，个别窗口读不到工具栏时会提示手动处理。

两者互不替代：第 2 步能永久减少 Outlook 导出的体积，但零散的小 HTML 仍需第 1 步清理。改完后重新导出并从界面「刷新」即可。

桌面启动时读入日历、地点和配置，应用内保存会更新界面。外部改文件后点击对应刷新按钮，应用不定时重读文件。地点管理和排除设置的刷新按钮位于文件标题旁。新增前端文件时，同步检查桌面静态白名单、移动复制清单以及 Service Worker 缓存清单。

## 代码更新与交接

本轮功能基线为已推送的 `0ed710b`，包含单行筛选、直接 PNG 导出、按需加载和日历解析优化。接手从仓库根目录的 [AGENTS.md](../AGENTS.md) 开始，结合 Git 状态和最近提交确认后续改动。交接时记录改动范围、完成的验证、未验证事项和提交或推送状态。

用合成数据跑 `npm test`，再按改动范围执行浏览器验证。使用说明、工程文件说明或配色约定有变化时，随对应功能更新。

| 改动范围 | 浏览器验证 |
| --- | --- |
| 启动、搜索或重复事件 | 在新会话确认事件列表先出现，时间、地点和排行处于收起状态，首屏无需请求全国边界。展开后检查统计和地图。连续输入时确认事件即时变化、打开的面板在停顿后刷新。检查回车提交、单项移除和两类筛选分别清除。 |
| 布局、控件或主题 | 检查桌面双栏、拖到最窄栏宽、手机单栏吸顶与标题高度。手机竖屏确认按钮等高，横屏确认主标题栏收起与排行／设置标签简写。检查日间、夜间、字号，以及分割条和高度手柄；iOS Safari 下确认日期控件文字居中。验证缩放或拖动分栏后瓦片补齐。 |
| 行程或年度回顾 | 实际点击「导出」并打开下载的 PNG。行程检查点位隐藏与恢复、预览与下载一致、底图署名和缺失瓦片时的点位保留。年度回顾检查直接下载。 |
| 本地文件或移动数据接口 | 验证桌面相应的刷新和替换入口，用合成文件验证移动端首次导入、替换与重载。 |

性能复测记录浏览器、事件数量和测量阶段，分别记录初次装载、输入到事件更新、延后面板更新。该基线上一次本机 Edge 测试使用 6,000 条合成事件，初次装载约 0.30 秒，搜索即时更新约 20–22 毫秒。

## 发布手机网页版

仓库 **Settings → Pages** 的发布源选用 **GitHub Actions**。推送到 `main` 后，`deploy-pages` 先跑合成数据测试，再以 `--data-less` 构建并检查产物，随后把 `mobile/` 发布到 GitHub Pages。按当前任务决定是否发布，单纯更新私人日历、地点或配置不需要推送。首次发布或需要手动重发时，可在 **Actions → deploy-pages → Run workflow** 操作。 [GitHub Pages 工作流说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

1. 核对 Git 工作区和本轮授权范围。提交前用 `git diff --cached --name-only` 核对暂存文件，并运行 `git diff --cached --check`。私人日历、地点库、配置、备份、报告、缓存、照片和签名留在本地。检查手工新增的文件和公开构建产物。
2. 在测试副本运行 `node tools/build-mobile.mjs --data-less`。改动 HTML、模块、样式资源或动态加载路径时，核对桌面静态白名单、移动包复制清单和 Service Worker 的预缓存及按需缓存清单。
3. 用桌面根路径和移动版 `/calendar-atlas/` 子路径分别验证涉及的功能。检查点击后才加载的模块和数据。例如 `app.js` 通过 `import('./lib/trip-share.js')` 加载行程导出模块，核对两端的实际请求与 PNG 下载。用合成文件验证移动导入及 Service Worker 生效。
4. 按本轮授权推送。推送后核对本地与远端提交。如果本轮要求确认网页版发布，还需查看 Pages 工作流结果，并在网页偏好中核对应用版本。PWA 会更新 Service Worker 缓存，设置或弹窗打开时会推迟自动重载。

公开仓库中的提交也包含作者和提交者邮箱。提交前用 `git var GIT_AUTHOR_IDENT` 和 `git var GIT_COMMITTER_IDENT` 在本机核对，可使用 GitHub 提供的 noreply 邮箱。更新 Git 邮箱只影响之后的提交。

## 本地移动网页

- `node tools/build-mobile.mjs --data-less` 创建支持导入的网页包。
- `node tools/build-mobile.mjs` 复制当前 `atlas-data` 生成含私人数据的本地网页包。
- `node mobile/serve.mjs` 在端口 8790 提供已生成的网页，访问 `http://127.0.0.1:8790/`。该预览服务器监听所有网络接口，含数据版本只在可信网络使用。调试发布模式时优先构建不含数据的版本。可从浏览器导入 [测试日历](../tests/fixtures/fixture.ics)、[测试地点](../tests/fixtures/place.csv) 和 [测试配置](../tests/fixtures/config.json)。
- 移动网页安装时缓存启动所需的应用资源。全国、上海和国家或地区地图数据、城市索引及热力图在首次使用时读取并缓存。在线瓦片由所选底图服务提供。
- `mobile/` 是构建输出。重新构建会替换这个目录。

## ZIP 备份和恢复

1. 先双击 **关闭足迹.cmd**，确保快照期间活动文件保持一致。
2. 将源码、启动与关闭入口、文档、公开地图、`.github/`、测试和完整的 `atlas-data/` 复制到同一个临时目录，再把副本打成 ZIP。要保留生成的历史报告时也复制 `temps/`。
3. 把 ZIP 放在项目目录之外。跳过 `.git/`、`mobile/`、`node_modules/`、其他已有压缩包和任何密钥。这个 ZIP 含私人日历及地点，保存在受控位置。
4. 验证时解压到一个新目录，确认能看到项目入口和 `atlas-data/calendar.ics`、`atlas-data/place.csv`、`atlas-data/config.json`，再执行 `npm test`。需要迁移到新电脑时，使用解压后的工程双击 **启动足迹.cmd**。
5. 如果要用备份替换现有工程，先单独保存现有的 `atlas-data/`，再替换并重启。若只需找回某次地点或配置保存前的状态，可从 `atlas-data/.backups/` 选择单个文件恢复。

ZIP 是源码和数据快照。浏览器偏好和 Git 历史需要分别迁移。
