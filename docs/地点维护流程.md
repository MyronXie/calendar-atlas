# 地点维护流程与名称匹配规则

地点主库为 `atlas-data/place.csv`。在工程根目录运行下列命令；查询前在当前 PowerShell 会话设置 `AMAP_KEY`。在线核验可能向地图服务发送待查地点名称或坐标。查询结果放在 `temps/`（已忽略、可随时清理），请先核对再写回。同日重跑默认覆盖当日报告和决策表，保留手工修改时请另存或使用 `--out` 和 `--decisions` 指定新路径。

## 字段

| 字段 | 含义 |
| --- | --- |
| `location`、`aliases` | 主名称和用分号分隔的别名 |
| `address`、`adcode` | 地址和六位行政区划码，境外行政区划码可留空 |
| `lat`、`lon`、`datum` | 纬度、经度和坐标系。高德返回 GCJ-02 |
| `firstShown`、`lastShown` | 日历首次和最后一次出现的日期，格式为 `YY/MM/DD` |
| `valid` | 日期表示上次核验在营，`no` 表示停业，`skip` 或空值进入下次核验 |
| `type`、`labels` | 地点分类和以分号分隔的标签 |

## 名称匹配规则

### 日历与地点库

程序读取事件的 `LOCATION` 和备注中的 `Place：` 行。地点管理工具用 `place.csv` 的 `location` 和 `aliases` 匹配这些名称，比较前进行 NFKC 归一化、转小写并移除标点与空白（见 `lib/place-name.js` 的 `loose`）。日历仍可使用登记过的别名。

地图候选的品牌相似度取括号前的名称，以最长连续公共子串除以较短核心的长度。括号常用于区分分店，核对结果时要同时看完整名称、商场、行政区、地址和距离。同一商场里的两家店可能名称相近，同一品牌也可能在不同区开店。

### 日历地点同步

先按名称或别名匹配主库。没有命中时，用高德和百度的文本搜索召回候选。归一化名称完全匹配的候选进入新增清单，品牌相似度达到 0.6 的候选进入改名核对清单。其余候选列在报告中供确认。

### 地点有效性核验

国内地点用高德和百度检索名称，并搜索原坐标附近 80 米的 POI。完全同名、附近同名或附近品牌相似度达到 0.7 时建议保留。名称不同且品牌相似度达到 0.6 时建议核对改名。附近 60 米有其他候选时列为疑似停业，其余进入人工核验。境外候选使用 OSM/Photon 的名称搜索和逆地理编码，结合距离与名称判断。

建议改名或停业时，先用门牌、商场或近期公开资料确认。店铺更名、搬迁和同名分店应分别判断。

## 更新日历后同步地点

1. 更新 `atlas-data/calendar.ics`。可先用桌面偏好里日历行的加号预览变更，确认后备份并替换。
2. 运行 `npm run sync`。根据报告确认直接匹配、待新增和待核对的地点（判定见上文「名称匹配规则」）。
3. 核对当天生成的 `日历地点同步_决策_<日期>.csv`。已有地点改名用 `rename`，并在 `location_old` 填主库名称或别名。新地点用 `add`。同一新地点若有多个名称，可在新增后通过地点管理补别名。
4. 按实际生成的文件名执行下方写回命令。同步模式会同时按日历重算库内匹配地点的首次和末次出现日期。

```powershell
npm run apply -- --mode sync --decisions "temps/日历地点同步_决策_<日期>.csv"
```

## 定期核验营业状态

1. 运行 `npm run verify -- --months 3`。脚本跳过已停业记录和最近 90 天核验过的记录。改用其他月份时，阈值按每月 30 天计算。
2. 核对当天生成的报告和 `地点有效性核验_决策_<日期>.csv`。确认仍营业用 `keep`，改名用 `rename`，已停业用 `closed`。资料不足时可移除对应决策行，留待下次确认。
3. 按实际生成的文件名执行写回命令。每次写入前会在 `atlas-data/.backups/` 保存副本。

```powershell
npm run apply -- --mode verify --decisions "temps/地点有效性核验_决策_<日期>.csv"
```

## 决策表格式

```csv
location_old,action,new_name,lat,lon,adcode,note
新地点,add,新地点,31.23,121.47,310115,确认新增
原店名,rename,新店名,31.23,121.47,310115,确认改名
正常营业地点,keep,,,,,更新核验日期
已停业地点,closed,,,,,确认停业
```

`rename` 会保留原名称用于匹配日历。`keep` 和 `rename` 会将营业核验日期更新为当天。地址、分类、标签与坐标系可在 **设置 → 地点管理** 维护。

外部写回后，在桌面地点管理的 `place.csv` 标题旁点击刷新。缺坐标时运行 `npm run pending`，填写生成的待补清单，再把核对过的记录追加或合并到主库。纯本地的日历格式检查使用 `npm run audit`。照片地点提取和日常区域排除见 [使用说明](使用说明.md#从照片提取地点行程)。
